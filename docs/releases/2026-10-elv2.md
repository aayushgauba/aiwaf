## Licensing change

Original project code uses standard Elastic License 2.0. Commercial use,
modification, redistribution, installation, and consulting remain permitted
subject to ELv2. Offering substantial AIWAF functionality as a hosted or
managed service requires separate permission. ELv2 also protects license-key
functionality and required notices.

Earlier MIT distributions retain their MIT permissions. Retained MIT
contributions remain separately licensed. IPinfo Lite remains CC BY-SA 4.0.
See the root LICENSE, NOTICE, and licenses/MIT.txt. Multi-component Python
and npm metadata uses an AND license expression, not an MIT alternative for
the entire package.

## Preparation and validation

- Package manifests, the Python runtime version, and local Rust lock entries
  are synchronized for these candidates. Existing dependency constraints
  remain unchanged and continue to permit compatible earlier accelerators.
- Packaging stages LICENSE, NOTICE, and licenses/ into the applicable Python,
  npm, Rust/Python, WASM, and Java artifacts.
- Documentation and its search index describe ELv2 and the preserved exceptions.

Before publication, run the existing package release workflows and required
test, security, signing, and package-content checks. Build native Rust and
WASM artifacts in those workflows; a metadata fixture does not verify native
binaries. Recheck version availability immediately before publication.

Pushing release tags can trigger publication. This preparation creates no
release tags and publishes no artifacts.
